03 필요한 사람

그래서 이 자리에는 이런 네 가지가 필요하다고 봤습니다

  1. 01

    현업의 의심에 운영 언어로 답하는 사람

    F1 0.7을 마케터가 의심했고, 해석력이 중요했다는 말이 발표마다 나온다.108

    제 근거 · 고독사 판별
  2. 02

    흐트러진 원천을 믿을 수 있는 데이터로 바꾸는 사람

    상담사 입력은 오매핑되고 STT 원문엔 오탈자가 많다. 현직자도 '모델링보다 데이터를 어떻게 정제했고 어떻게 가져왔는지'를 강조했다.1114

    제 근거 · 양천 STT · 상담 음성
  3. 03

    정답 없는 LLM 출력에 채점 기준을 세우는 사람

    Loss가 낮다고 답이 좋아지지 않았고, 평가는 25케이스 · 50문항 같은 작은 사람 채점셋이었다.910

    제 근거 · 블잇 · 벤치마크
  4. 04

    LLM의 자유도를 구조로 묶는 사람

    그래프는 규칙으로 고정하고 SQL은 self-correction 루프로 돌렸다. 2023년 PoC에서는 논리형 질문이 약점으로 남았다.109

    제 근거 · 복지 Agent

양천구청 AI 민원창구 STT · 상담 음성 STT

Whisper를 행정 용어로 추가 학습해 실제 상담 350건으로 상용 STT와 같은 기준(CER)에서 비교했고, 1차 실증 개선 요구 78건을 원인별로 나눈 뒤 평가 데이터를 조건 4 × 단계 2, 8구간으로 쪼갰다. 상담 음성 과제에서는 sLLM 후처리로 용어 · 띄어쓰기를 회수했다.

같은 점
  • 상담 음성의 전사 품질이 뒤의 분석을 막는다
  • LLM으로 전사본을 정제한다
  • 상담을 유형으로 묶는다(의도 분류기)
다른 점 · 해 보지 않은 것
  • 규모: 월 약 50만 건과 평가셋 350건
  • 임베딩 군집으로 택소노미를 '만든' 적은 없다 — 정해진 라벨로 분류만 했다
  • 사외 데이터(커뮤니티 · 포털) 결합은 해 보지 않았다

가져갈 것정제 전후로 무엇이 지켜졌는지(숫자 · 상품명 보존, 마스킹 재현율)를 구간별로 재는 평가표

놓치면 안 되는 문제라 계획서의 F1 대신 재현율을 앞에 두고, 파생변수를 다시 설계해 조합을 같은 기준에서 비교했다. 재현율 하한 안에서 사람이 볼 양이 가장 적은 기준값을 골랐고 근거는 SHAP으로 붙였다.

같은 점
  • 점수 · 구간 · 운영 기준으로 이어지는 흐름
  • 현업에게 F1 대신 운영의 언어로 말하기
  • 적고 불균형한 데이터 · 해석력 우선
다른 점 · 해 보지 않은 것
  • 비용 구조가 반대: 오퍼 대비 반응(정밀도)과 놓치면 안 되는 재현율
  • 온라인 A/B로 검증해 본 적은 없다 — 오프라인 검증까지
  • 운영점은 테스트셋으로 정한 사후 분석이라 운영에선 검증용 데이터로 다시 정해야 한다

가져갈 것모델을 고르기 전에 '놓치면 얼마인가 · 사람이 몇 건을 볼 수 있나'를 현업과 먼저 정하는 순서

복지 상담 RAG · Agent PoC

폐쇄망 소형 LLM 에이전트를 LangGraph로 엮되, 실행마다 달라지던 경로를 '판정은 규칙, 설명은 LLM'으로 나눠 고정했다. 사례별 기대 경로를 LLM 없이 먼저 테스트하고 고위험 판단은 공무원 승인(HITL)으로 남겼다.

같은 점
  • LLM 자유도를 규칙 뼈대로 묶는다
  • 고정된 테스트로 회귀를 막는다
  • Agent로 가기 전에 사람이 확인할 지점을 정한다
다른 점 · 해 보지 않은 것
  • Text2SQL · 다중 테이블 스키마 검색은 해 보지 않았다
  • PoC 단계 — 현업 운영 기록은 없다

가져갈 것모델을 바꿔도 같은 판단이 나오는지 LLM 없이 도는 기대 경로 테스트로 확인하는 회귀 기준

B world 공개 FAQ 288건으로, 고객의 말이 맞는 답에 닿는지 재 봤습니다

SK브로드밴드 공개 페이지(2026-10-14 수집)15와 제가 직접 쓴 평가 문장 80개로 한 연습입니다. 내부 상담 로그나 고객 데이터는 쓰지 않았고, 실제 챗봇 성능과는 관계가 없습니다.

데이터

FAQ 288건(8개 분류)의 질문과 답

평가 문장

80개 = 표준 질문 · 구어체 · STT 잡음 · 고객 말 ≠ FAQ 말, 각 20개

정답

받아들일 수 있는 FAQ 묶음 — 23개 문장(29%)은 맞는 FAQ가 둘 이상

잰 것

1위 정답률 · 3위 안 정답률 · 조건별 · 자동 응답 범위와 정확도

  1. 받아쓴 말에는 글자 조각이 강했습니다. 띄어쓰기가 붙거나 소리 나는 대로 적힌 문장에서 단어 검색은 35%, 글자 조각 검색은 80%를 맞혔습니다.
  2. 가장 약한 칸은 구어체였습니다. 맥락을 먼저 말하는 긴 문장은 어떤 방식으로도 절반 안팎에 머물렀습니다. 평균(68%)만 보면 보이지 않는 칸입니다.
  3. 자동으로 답할 범위를 좁히면 정확해집니다. 1위 점수가 기준을 넘는 문장만 답하게 하면 30%를 92% 정확도로 답했습니다. 나머지는 되묻거나 상담사에게 넘겨야 합니다.
  4. 정답이 하나가 아니었습니다. 일시정지는 ‘가입 및 변경’과 ‘요금 및 납부’에, 설치까지 걸리는 시간은 ‘인터넷’과 ‘가입 및 변경’에 함께 있습니다. 평가 전에 정답 묶음부터 정해야 했습니다.

틀린 예(최종 방식)

  • “아 저기 어제부터 와이파이가 자꾸 끊겼다 붙었다 하는데요 이거 왜 그런 거예요”1위로 찾은 것 · 방에서는 와이파이가 잘 안 터지는 것 같아요. 어떻게 해야 하나요?정답 · 인터넷이 가끔 끊어지는데 왜 그런가요? 6위
  • “군대 가게 됐는데 그동안 인터넷 요금 계속 내야 돼요”1위로 찾은 것 · 인터넷 출동비는 무엇이며 어떻게 내야 해요?정답 · 군 입대, 유학 등으로 인터넷 이용을 잠시 정지도 가능한가요? 8위
  • “인터넷 끊고 나면 모뎀이랑 셋톱박스는 어떻게 돌려드려요”1위로 찾은 것 · 셋톱박스는 판매도 하나요?정답 · 해지 후 임대장비(모뎀, 셋탑박스 등)는 어떻게 반환해야 하나요? 18위
  • “엄마 명의로 된 인터넷인데 제가 대신 해지해도 되나요”1위로 찾은 것 · 인터넷을 해지해도 요즘가족결합 할인을 받을 수 있나요?정답 · 개인 인터넷 해지시 가입자가 아닌 대리인도 해지 신청 가능한가요? 33위

입사하면 다르게 할 것 실제 상담 로그로 조건을 다시 정의하고(고령층 말투 · 통화 STT), 확신이 낮은 문장에는 되묻는 질문을 설계하고, LLM은 질문을 고쳐 쓰는 데만 쓰고 답은 정해진 FAQ에서 고르겠습니다. 이 연습의 용어 사전 11개는 평가 문장을 쓴 제가 만들었기 때문에 그 개선 폭은 낙관적인 값입니다.

06 첫해와 모르는 것

첫 업무 순서에 맞춰 할 일 셋, 아직 모르는 것 넷

  1. AI Tool · 모델 검증

    새 모델을 들이기 전에 조건별 평가셋부터 — 평균 하나 대신 소음 · 말 겹침 · 구어체 칸

  2. RAG · Agent 프로토타입

    판정은 규칙, 설명은 LLM — 바뀐 모델이 어제의 답을 깨지 않는지 기대 경로로 회귀 테스트

  3. 실제 업무 데이터 성능 검증

    놓치면 안 되는 하한과 사람이 볼 양을 현업과 같이 정해 운영 기준으로 남기기

  • BSS 데이터

    가입 · 개통 · 청구 · 유지 흐름의 데이터는 다뤄 본 적이 없다. 마트의 테이블 관계부터 익히겠다.

  • 온라인 실험

    A/B · uplift로 효과를 재 본 적이 없다. TASTE의 스코어 × 오퍼 교차 설계부터 배우겠다.

  • 군집 택소노미

    임베딩 군집으로 유형 체계를 만든 적이 없다. 정해진 라벨 분류까지만 해 봤다.

  • 대규모 운영

    Spark · SageMaker · Airflow 위에서 모델을 운영해 본 적이 없다.
