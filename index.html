고민 1/2계획서의 F1 대신 놓치지 않는 재현율을 앞에 뒀어요

  1. 본 것첫 결과는 평균 지표가 좋아 보였지만 고독사 비율이 낮아 정밀도가 떨어지며 F1이 무너졌어요. 계획서의 주 지표는 F1이었어요.
  2. A · 고르지 않은 쪽F1을 끝까지 맞춘다계획서대로 균형을 맞춘다. 그만큼 놓치는 건이 늘 수 있다
  3. B · 고른 쪽재현율을 앞에 둔다놓치지 않는 쪽을 모델이 맡고, 잘못 잡은 건은 사람이 검수에서 거른다
  4. 판단“고독사는 절대 놓치면 안 된다”는 실무자와 기관의 의견을 받아 재현율을 우선 지표로 바꿨어요. 정밀도 부담은 사람 검수로 넘기고 판정마다 확률과 SHAP 근거를 붙였어요.

고민 2/2모델을 키우는 대신 변수를 다시 봤어요

  1. 본 것좋은 결과는 사람이 채운 파생변수 덕분이었고, 실제로 쓰일 데이터에는 그 변수가 없었어요.
  2. A · 고르지 않은 쪽모든 변수를 글에서 예측사람 손을 완전히 없앤다. 예측이 틀리면 판별도 함께 틀린다
  3. B · 고른 쪽영향이 큰 변수만 채운다SHAP으로 추린 핵심 변수만 사건 개요 글에서 채우고 나머지는 원시 데이터로
  4. 판단피처 · 텍스트 처리 · 모델을 같은 분할과 같은 지표로 비교해 텍스트 없이 확장 파생변수만 쓴 랜덤 포레스트를 골랐어요. 모든 변수를 글에서 채우려다 성능이 무너지는 걸 보고 영향이 큰 변수만 채우도록 좁혔고, 실패한 시도도 보고서에 남겼어요.

첫해에 할 일

  1. 01AI Tool · 모델 검증

    새 모델을 들이기 전에 조건별 평가셋부터 — 평균 하나 대신 소음 · 말 겹침 · 구어체 칸

  2. 02RAG · Agent 프로토타입

    판정은 규칙, 설명은 LLM — 바뀐 모델이 어제의 답을 깨지 않는지 기대 경로로 회귀 테스트

  3. 03실제 업무 데이터 성능 검증

    놓치면 안 되는 하한과 사람이 볼 양을 현업과 같이 정해 운영 기준으로 남기기

아직 모르는 것

  1. 04BSS 데이터

    가입 · 개통 · 청구 · 유지 흐름의 데이터는 다뤄 본 적이 없다. 마트의 테이블 관계부터 익히겠다.

  2. 05온라인 실험

    A/B · uplift로 효과를 재 본 적이 없다. TASTE의 스코어 × 오퍼 교차 설계부터 배우겠다.

  3. 06군집 택소노미

    임베딩 군집으로 유형 체계를 만든 적이 없다. 정해진 라벨 분류까지만 해 봤다.

  4. 07대규모 운영

    Spark · SageMaker · Airflow 위에서 모델을 운영해 본 적이 없다.
