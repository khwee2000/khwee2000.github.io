01 문제 정의

주어진 문제를
이렇게 다시 정의했어요

re-
define

문제 다시 보기

  • 주어진 문제복지사각지대 발굴 대상자의 초기 상담을 AI 에이전트가 도와주는 행정업무 지원체계를 설계한다.
  • 다시 정의한 문제AI가 대상자를 판정하면 안 됐어요. 판정은 공무원의 권한이고, AI는 여러 시스템에 흩어진 정보를 모아 근거를 붙인 상담 준비물을 만드는 쪽이어야 했어요. 그래서 모든 추천에 출처를 달고, 사람이 승인해야만 기록이 남게 했어요.

02 동작 구조

이렇게
돌아가요

위기정보 입수→정보수집 Agent→위기판단→자원 추천 + 근거→담당자 확인→기록 · A4 시트

대상자 한 명에 대해 네 단계 에이전트가 차례로 돌고, 오케스트레이터가 결과를 비평해 부족하면 다시 요청해요. 파란 단계가 제가 설계하고 만든 부분이에요.

합성 데이터로 돌린 작동 데모예요 · 화면의 이름과 수치는 모두 가상이에요

Grounding
모든 추천에 근거 법령과 수집 사실을 붙이고, 출처를 못 단 항목은 화면에 내보내지 않아요
Human in the loop
추천과 기록 두 단계에서 담당자가 승인 · 수정 요청 · 반려를 고르고, 반려하면 에이전트가 다시 돌아요
Auditability
누가 무엇을 승인했는지, 어떤 자원이 왜 탈락했는지까지 전부 로그로 남아요

03 내 판단

이렇게 판단하고 움직였어요

01

판정은 규칙으로, 서술만 LLM에게 맡겼어요

응급 · 반복 · 기존 · 최초의 대상 구분, 위기유형과 복지욕구의 매칭, 자원을 걸러내는 네 단계 퍼널은 전부 결정적 규칙으로 뒀어요. LLM은 그 결과를 사람이 읽을 문장으로 요약만 해요. 같은 입력이면 언제나 같은 결과가 나와요.

02

출처 없는 추천은 화면에 내보내지 않았어요

추천마다 근거 법령과 수집 사실을 붙이고, 출처를 못 단 항목은 탈락 사유와 함께 기록에만 남겨요. 자살 관련 신호가 없는 대상자에게는 자살예방 자원이 추천되지 않도록 신호 게이트를 따로 뒀어요. 많이 추천하는 것보다 틀리지 않는 쪽을 골랐어요.

03

사람이 멈출 수 있는 자리를 두 번 만들었어요

추천 단계와 기록 단계에서 담당자가 승인 · 수정 요청 · 반려를 고르고, 반려하면 에이전트가 다시 돌아요. 응급 신호가 있으면 상담 대본을 만들지 않고 즉시 개입으로 넘겨요. 판단은 끝까지 공무원의 권한으로 남겼어요.

04

결과는 A4 한 장으로 고정했어요

공무원이 들고 나갈 수 있게 화면과 인쇄와 PDF가 같은 한 장이 되도록 레이아웃을 고정했어요. 전화 스크립트는 1분 · 5분 · 10분 세 길이로 만들고, 응급이면 스크립트 대신 즉시 조치 순서가 들어가요. 소형 LLM이 한자를 섞어 내는 문제는 언어 가드로 결정적으로 막았어요.

04 결과

무엇이 바뀌었나

Before

대상자 명단을 받은 공무원이 여러 시스템을 돌며 상담 전 자료를 손으로 모았어요. 추천의 근거는 머릿속에만 있었어요.

→

제가 한 것

  • LangGraph로 정보수집 → 위기판단 → 자원 추천 → 기록 네 단계 에이전트와 비평 · 재요청 루프 구현
  • 모든 추천에 근거 출처, 승인 · 수정 · 반려 2단계 담당자 게이트
  • 행복이음 화면을 본뜬 데모와 A4 한 장 상담 준비 시트
→

After

  • 합성 대상자 시나리오로 응급 · 반복 · 기존 · 최초 네 상황의 전 과정을 재현
  • 연구 자문 회의에서 작동 데모로 설계를 검증하고 다음 설계의 입력으로 사용
  • 모델 교체는 환경변수 하나 — 로컬 소형 LLM에서 클라우드로 전환 가능
