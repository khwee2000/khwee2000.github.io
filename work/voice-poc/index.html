상담 음성 AI 활용 검증

상담 음성을 AI로 쓸 수 있는지를 숫자로 답하는 일

01

문제 정의

주어진 문제상담 음성을 AI로 활용할 수 있는지 검증해야 했어요. 한국어 상담 음성은 잡음과 겹말이 많고 제도 용어가 계속 나와 범용 모델 성능이 재현되지 않았어요. 개인정보가 담겨 외부 API도 쓸 수 없었어요.

성능을 올리는 일과 성능을 증명하는 일은 달라요. 어떤 조건에서 쓸 수 있고 어디서 무너지는지를 답해야 했어요.

02

동작 구조

  1. 01상담 음성
  2. 02음성 인식
  3. 03후처리 교정제가 맡은 부분
  4. 04개인정보 비식별화
  5. 05구간별 평가제가 맡은 부분

03

내 판단

  1. 01

    계약 전에 안 되는 것부터 말했어요

    정답 데이터를 어떻게 확보할지와 목표 수치가 현실적인지와 요구된 모델 사양이 맞는지와 일정이 감당되는지를 먼저 꺼냈어요. 계약을 빨리 맺는 데는 도움이 안 되는 이야기였지만 착수 뒤에 드러났다면 되돌릴 수 없었을 위험이었어요.

  2. 02

    사양을 직접 재서 정했어요

    처리할 양을 기한으로 나눠 하루 처리량을 역산하고 모델별 GPU 메모리와 추론 속도를 쟀어요. 단일 구성으로는 기한을 못 맞춘다는 게 숫자로 확인돼 병목을 비교한 뒤 병렬로 구성했고 서버 구성별 속도와 비용을 비교해 사양을 정했어요.

  3. 03

    인식과 교정을 두 단계로 나눴어요

    오류를 뜯어보니 특정 용어와 띄어쓰기에 몰려 있었어요. 인식 단계에서 다 잡기보다 소형 LLM 후처리로 회수하는 편이 비용 대비 효과가 컸어요.

  4. 04

    평균이 아니라 구간별로 평가했어요

    전체 평균 대신 발화 길이와 용어 밀도로 구간을 나눠 평가해 어디서 무너지는지를 드러냈어요.

04

결과

Before

범용 음성 인식 성능이 상담 음성에서는 재현되지 않았고 외부 API도 쓸 수 없었어요. 쓸 수 있는지에 대한 답이 없었어요.

→

제가 한 것

  • 계약 전에 쟁점 4가지(정답 데이터 · 목표치 · 모델 사양 · 일정)를 먼저 제기
  • 처리량 역산과 GPU 메모리 · 추론 속도 측정으로 서버 사양 결정
  • 인식 + 소형 LLM 후처리 2단 구조와 구간별 평가
→

지금까지 확인한 것

  • 하루 처리량 역산과 온프레미스 서버 사양 산정
  • 폐쇄망 안 음성 인식 → 개인정보 탐지 → 비식별화 파이프라인
  • 인식 + 후처리 2단 구조로 용어 · 띄어쓰기 오류 회수
  • 발화 길이 · 용어 밀도별 구간 평가 기준
