CASE 04

대화형 복지 추천과 자격 판정 벤치마크

비교할 기준이 없던 복지 추천에서 자격 정답표로 채점하는 추천

제 역할

기술

사례 전체 읽기

고민 사람이 읽고 평가하는 대신 자격 정답표로 같은 기준에서 비교했어요

  1. 본 것복지가 필요한 사람일수록 자기가 어떤 제도의 대상인지 모른 채 상담에 와요. 추천은 정답이 정해져 있지 않아 어떤 방식이 나은지 비교할 기준이 없었어요.
  2. A · 고르지 않은 쪽사람이 결과를 읽고 평가빠르지만 평가자마다 기준이 달라 방식끼리 비교가 안 된다
  3. B · 고른 쪽자격 정답표를 먼저 만든다정책 × 사람 칸마다 자격을 정해 두고 모든 방식을 같은 표로 채점한다
  4. 판단연구팀은 정책 4,937건 × 페르소나 180명의 셀 단위 정답표로 여러 추천 구조를 같은 기준에서 비교했고, 저는 조건을 한꺼번에 묻는 대신 대화로 하나씩 끌어내는 추천 파이프라인을 설계했어요.

SK브로드밴드에 옮기면

  1. 01sLLM PoC 평가(2023) · TASTE 도우미 평가(2024)910

    sLLM PoC는 5분류 × 3표현 50문항을 사람이 채점했고 절차 · 추천 · 비교 같은 논리형 질문이 약했다. TASTE 도우미는 난이도 3단계 25케이스를 4지표로 쟀다.

    50문항 5분류 × 3표현 사람 채점25케이스 난이도 3단계 · 4지표논리형 절차 · 추천 · 비교 질문이 약점

  2. 02같은 점
    • 층을 나눈 평가셋을 먼저 만든다
    • 논리형 판단(자격 · 사실)은 LLM에 맡기지 않는다
  3. 03다른 점 · 해 보지 않은 것
    • 정답표는 연구팀이 만들었다 — 제 몫은 대화형 추천 파이프라인
    • LLM 판정기와 사람 채점의 일치도는 따로 재 본 적이 없다
  4. 04가져갈 것

    정답이 정해진 질의셋, 채점 루브릭, 사람과 판정기 일치도 순서로 평가를 세우는 습관
