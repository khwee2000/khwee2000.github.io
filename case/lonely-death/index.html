F1이 좋으면 써도 될까? 고독사 판별에서 기준부터 다시 세운 방법

김민수 · 전처리 · 파생변수 · 모델 비교 · 성능 평가

2025년 11월 – 2026년 1월 · 공공기관 공동연구 PoC

안녕하세요. 공공 상담 · 복지 데이터로 모델을 만들고 평가 기준을 세워 온 김민수예요.

법에 따라 고독사 통계를 내려면, 담당자가 사건 기록을 한 건씩 읽고 고독사인지 아닌지를 가려야 해요. 사건 개요 같은 긴 글을 직접 읽고 판단하다 보니 처리가 늦었고, 같은 기록을 보고도 사람마다 판단이 달랐어요.

그래서 기록을 자동으로 분류하는 모델을 만들기로 했는데요. 만들고 나서 보니 진짜 문제는 모델이 아니라 무엇을 성공으로 볼지였어요.

결론부터 말하면, 놓치지 않는 기준을 지키면서 사람이 직접 볼 사례를 전체의 일부로 줄였고, 계획서에서 목표로 잡은 성능 기준도 모두 넘겼어요. 기관 과제라 수치는 싣지 않았어요. 이 글에서는 그 기준을 어떻게 다시 세웠고, 그 과정에서 어디서 틀렸는지를 순서대로 적어 볼게요.

평균이 좋은데, 왜 그대로 쓸 수 없었을까요?

첫 결과는 평균 지표만 보면 좋아 보였어요. 그런데 고독사는 전체 기록 가운데 비율이 낮은 사건이에요. 비율이 낮은 쪽을 잡으려 하자 정밀도가 떨어지면서, 계획서가 주 지표로 잡은 F1이 무너졌어요.

여기서 선택지가 둘이었어요. 계획서대로 F1을 끝까지 맞추는 것, 아니면 지표 자체를 다시 보는 것. F1을 맞추려면 정밀도와 재현율의 균형을 잡아야 하는데, 그만큼 놓치는 사건이 늘 수 있었거든요.

그래서 질문을 바꿨어요.

정확한 모델이 아니라, 놓치지 않는 모델이 필요한 게 아닐까?

그리고 담당자가 왜 그렇게 판단했는지 확인할 수 있어야 하고, 데이터는 기관 밖으로 나갈 수 없었어요.

F1 대신 재현율을 앞에 두기

실무자와 기관에서 같은 말을 들었어요. “고독사는 절대 놓치면 안 된다.” 그래서 재현율을 우선 지표로 바꿨어요. 대신 잘못 잡은 건은 사람이 검수에서 거르게 했어요. 정밀도의 부담을 모델이 아니라 운영이 나눠 지는 셈이에요.

  • 재현율 — 실제 고독사 가운데 모델이 잡아낸 비율. 모델이 책임지는 쪽이에요.
  • 정밀도 — 모델이 고독사라고 한 것 가운데 맞은 비율. 사람 검수가 메우는 쪽이에요.
  • 검수량 — 사람이 직접 읽어야 하는 사례의 양. 줄여야 하는 비용이에요.

이렇게 나누고 나니, 남은 질문은 하나였어요. 재현율을 지키면서 검수량을 얼마나 줄일 수 있을까.

모델을 키우기 전에 변수부터 다시 봤어요

보통은 여기서 텍스트를 더 넣거나, 더 큰 언어 모델을 더 오래 학습시키는 쪽으로 가요. KoBERT로 사건 개요 글을 학습하는 방법도 비교 대상에 넣었어요.

그런데 성능을 가른 건 글이 아니라 도메인 변수였어요. 동거 여부, 발견 경위, 변사자 상태처럼 현장에서 판단에 쓰는 요인을 변수로 정리하자 결과가 달라졌거든요.

그래서 모델을 먼저 고르지 않고, 피처 구성 · 텍스트 처리 방식 · 모델 종류를 조합해 같은 분할과 같은 지표로 비교했어요. 결과는 의외였는데요, 텍스트를 빼고 확장 파생변수만 쓴 랜덤 포레스트가 가장 앞섰어요.

모델을 먼저 정했다면 못 봤을 결과예요.

현장 데이터에는 그 변수가 없었어요

여기서 한 번 크게 틀렸어요. 좋은 결과는 사람이 채워 둔 파생변수 덕분이었는데, 실제로 이 모델이 쓰일 데이터에는 그 변수가 없었어요.

처음에는 모든 변수를 사건 개요 글에서 예측해 채우려고 했어요. 사람 손을 완전히 없애는 방법이었죠. 그런데 예측이 틀리면 판별도 함께 틀렸고, 성능이 무너졌어요.

그래서 범위를 좁혔어요. SHAP으로 영향이 큰 변수만 추려서 그것만 글에서 채우고, 나머지는 원시 데이터로 판단하게 했어요. 실패한 시도는 지우지 않고 보고서에 함께 남겼어요. 다음 사람이 같은 길로 가지 않게요.

사람이 볼 몫을 운영 기준으로 정했어요

판정마다 확률과 SHAP 근거를 붙이고, 놓치지 않는 비율을 담당자가 화면에서 직접 고를 수 있게 했어요. 기본값은 재현율 95%로 두고, 확실한 건 자동 승인, 애매한 건만 검수 대기열로 보냈어요.

그리고 개인정보가 밖으로 나가지 않도록, 담당자 PC에서 혼자 도는 실행 파일로 만들었어요. 엑셀을 넣으면 판정과 확률이 나와요.

고려했지만 선택하지 않은 것

  • F1을 끝까지 맞추기 — 계획서와는 맞지만, 놓치는 건이 늘 수 있어서 내려놓았어요.
  • 더 큰 텍스트 모델을 더 오래 학습하기 — 변수를 정리한 조합이 더 적은 피처로 같거나 더 나은 결과를 냈어요.
  • 모든 변수를 글에서 자동으로 채우기 — 실제로 해 보고 성능이 무너지는 걸 확인한 뒤 버렸어요.

아직 남은 문제

솔직히 적어 둘 게 있어요. 지금의 운영점은 테스트셋 정답을 보고 정한 사후 분석이에요. 실제로 운영하려면 검증용 데이터로 다시 정해야 해요. 그리고 오프라인 검증까지만 했고, 온라인에서 효과를 재 본 적은 없어요.

SK브로드밴드에서라면

AT R&D가 공개한 일 가운데 이 문제와 같은 모양의 일이 있어요. TASTE 스코어링 · 콘텐츠 흥행 예측10이에요.

  • 공개된 내용 — 한정된 자원으로 최대 효과를 얻으려 고객을 점수로 줄 세우고, 스코어 구간과 오퍼를 교차해 검증했다. 흥행 예측은 적고 불균형한 데이터에서 해석력을 우선했다.
  • 같은 점 — 점수 · 구간 · 운영 기준으로 이어지는 흐름
  • 같은 점 — 현업에게 F1 대신 운영의 언어로 말하기
  • 같은 점 — 적고 불균형한 데이터 · 해석력 우선
  • 해 보지 않은 것 — 비용 구조가 반대: 오퍼 대비 반응(정밀도)과 놓치면 안 되는 재현율
  • 해 보지 않은 것 — 온라인 A/B로 검증해 본 적은 없다 — 오프라인 검증까지
  • 해 보지 않은 것 — 운영점은 테스트셋으로 정한 사후 분석이라 운영에선 검증용 데이터로 다시 정해야 한다

그래서 입사하면 먼저 가져가고 싶은 건 이거예요.

모델을 고르기 전에 '놓치면 얼마인가 · 사람이 몇 건을 볼 수 있나'를 현업과 먼저 정하는 순서

마치며

이 일에서 알고 싶었던 건 ‘얼마나 정확한가’가 아니라 ‘무엇을 놓치면 안 되는가’였어요.

  • 지표는 계획서가 아니라 현업이 정해요 — 놓치면 안 되는 쪽과 사람이 감당할 몫을 먼저 나누면, 고를 모델이 달라져요.
  • 성능은 모델이 아니라 변수에서 나왔어요 — 같은 분할 · 같은 지표로 조합을 비교했기 때문에 보인 결과예요.
  • 실패한 시도도 결과예요 — 모든 변수를 채우려다 무너진 기록이 다음 판단의 근거가 됐어요.

읽어 주셔서 감사해요.
