CASE 05

블잇 · 뉴스 기반 블로그 자동 발행

원문에 없는 내용이 섞이던 생성 글에서 사실을 따로 대조하는 3단계 검증

기간
2024.03 – 2024.06 · 데이터사이언스 캡스톤
함께한 곳
협업사 지하철온다 · 데이터사이언스 캡스톤디자인
제 역할
4인 팀장 · 수집 · 정제 · 통합 파이프라인
기술
Newspaper3k · Selenium · SpaCy · G-Eval · 생성형 AI
사례 전체 읽기

고민 평균 90.9점에도 날짜를 틀리는 글을 따로 잡았어요

  1. 본 것생성형 AI로 바꾸자 원문에 없는 내용이 섞였고, 원문과의 유사도(BLEU)로는 같은 내용을 다른 문장으로 쓴 글을 제대로 잴 수 없었어요.
  2. A · 고르지 않은 쪽유사도 점수를 올린다익숙한 지표지만 사실이 틀린 글도 점수가 높을 수 있다
  3. B · 고른 쪽사실 일치를 따로 잰다내용 완성도 · 가독성 · 사실 일치도로 평가하고 사실에 가장 큰 가중치
  4. 판단팀은 G-Eval 기반 평가로 바꾸고 생성을 세 단계로 나눠 65.8점을 90.9점으로 올렸어요. 그래도 날짜를 틀리는 글이 남아 날짜 · 노선 대조를 포함한 3단계 검증을 붙였고, 싼 검사부터 돌려 건당 84원이었어요. 저는 팀장으로 수집 · 정제 · 통합 파이프라인을 맡았어요.

SK브로드밴드에 옮기면

  1. 01가입 예측 + SHAP + LLM 상담 멘트(KICS 2025)13

    SHAP 상위 요인을 LLM에 넣어 고객별 멘트를 만든다. 논문은 생성 멘트의 품질 · 설득력 검증을 '향후 연구'로 남겼다(SKB 저자 논문 — 팀 소속은 확인하지 못했다).

    5만 명 인터넷 단독 고객F1 0.89 XGBoost(DBpia 요약)향후 연구 생성 멘트의 품질 검증

  2. 02같은 점
    • 예측 · 설명 · 사람이 읽는 문장으로 이어지는 구조
    • 생성 문장이 근거와 맞는지가 마지막 관문
  3. 03다른 점 · 해 보지 않은 것
    • SHAP 결과를 LLM 문장으로 바꿔 본 적은 없다 — 이어 본 것은 블잇의 생성문 검증
  4. 04가져갈 것

    멘트 속 주장을 다시 뽑아 입력 요인과 대조하는 '주장–근거 일치율'
