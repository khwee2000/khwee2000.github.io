CASE 02

양천구청 AI 민원창구

평균 오류율만 보던 민원 음성 인식에서 8구간에서 찾은 병목과 원인별 처방

기간
2025 · 1차 실증과 2차 실증
함께한 곳
양천구청 · 지산학 공동연구
제 역할
평가 기준 · 음성 인식 · 오류 분석 담당
기술
Whisper 파인튜닝 · Pyannote · RNNoise · VAD · 의도 분류
사례 전체 읽기

고민 평균 오류율을 더 낮추는 대신 조건별로 쪼개 병목을 찾았어요

  1. 본 것행정 · 법률 용어를 추가 학습해 같은 기준(글자 단위 오류율)에서 상용 음성인식보다 낮았어요. 그런데 시연에서 공무원은 “정확도보다 제 일이 얼마나 줄어드나요?”라고 물었어요.
  2. A · 고르지 않은 쪽평균 오류율을 더 낮춘다모델을 더 학습시킨다. 업무를 막는 오류가 어디서 나오는지는 여전히 모른다
  3. B · 고른 쪽조건별로 쪼개 본다업무를 막는 오류가 어떤 상황, 어느 단계에서 나오는지 먼저 찾는다
  4. 판단개선 요구 78건을 인식 · 환경 · 업무 흐름으로 나누고 평가 데이터를 4개 조건 × 2개 단계, 8개 구간으로 다시 봤어요. 자유 대화 × 요약 칸에서 업무와 무관한 말까지 민원으로 요약하는 문제가 나와 의도 분류기 · 화자 분리 · 소음 증강을 원인마다 붙였어요.

SK브로드밴드에 옮기면

  1. 01VISTA · 상담 STT VoC 분석11

    상담 STT를 LLM으로 정제 · 요약 · 마스킹하고 유형으로 묶어 검색 API · MCP로 낸다. 원천 문제로 'STT 오탈자'와 상담사 입력의 오매핑을 꼽았다.

    월 약 50만 건 상담 STT 원문80% 이상 데이터 추출 투입 시간 감소(기대)5명 5년차 이하 주니어가 자체 개발

  2. 02같은 점
    • 상담 음성의 전사 품질이 뒤의 분석을 막는다
    • 전사 뒤에 분류 · 요약을 붙여 쓸 말만 남긴다(의도 분류기 · 유형별 요약 템플릿)
  3. 03다른 점 · 해 보지 않은 것
    • 규모: 월 약 50만 건과 평가셋 350건
    • 임베딩 군집으로 택소노미를 '만든' 적은 없다 — 정해진 라벨로 분류만 했다
    • 사외 데이터(커뮤니티 · 포털) 결합은 해 보지 않았다
  4. 04가져갈 것

    정제 전후로 무엇이 지켜졌는지(숫자 · 상품명 보존, 마스킹 재현율)를 구간별로 재는 평가표
